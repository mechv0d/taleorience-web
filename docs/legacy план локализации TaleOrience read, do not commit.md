# Дополнение к ТЗ: система локализации World Engine

## Общая идея

World Engine должен проектироваться с учётом локализации с самого начала
разработки.

Вместо хранения пользовательского интерфейсного текста напрямую в коде
или компонентах UI необходимо использовать систему локализации.

Запрещается:

``` ts
<Button>
    Create Project
</Button>
```

Предпочтительный вариант:

``` ts
<Button>
    {t("project.create")}
</Button>
```

где текст берётся из файла локализации.

------------------------------------------------------------------------

## Цель

Система локализации должна позволять:

-   переводить интерфейс приложения;
-   добавлять новые языки без изменения кода;
-   поддерживать пользовательские переводы;
-   отделять доменную логику от отображаемого текста;
-   подготовить проект к международному использованию.

------------------------------------------------------------------------

## Структура файлов локализации

Пример:

    locales/

    ├── en/
    │   ├── common.json
    │   ├── projects.json
    │   ├── editor.json
    │   └── errors.json
    │
    ├── ru/
    │   ├── common.json
    │   ├── projects.json
    │   ├── editor.json
    │   └── errors.json
    │
    └── jp/
        ├── common.json
        ├── projects.json
        ├── editor.json
        └── errors.json

------------------------------------------------------------------------

## Пример файла локализации

`projects.json`

``` json
{
    "create": "Create Project",
    "rename": "Rename Project",
    "delete": "Delete Project",
    "clone": "Clone Project",
    "description": "Description"
}
```

Русская версия:

``` json
{
    "create": "Создать проект",
    "rename": "Переименовать проект",
    "delete": "Удалить проект",
    "clone": "Клонировать проект",
    "description": "Описание"
}
```

------------------------------------------------------------------------

## Правило ключей

Ключи локализации должны описывать смысл, а не конкретный текст.

Плохо:

``` json
{
    "blue_button_text": "Create"
}
```

Хорошо:

``` json
{
    "project.create": "Create Project"
}
```

или:

``` json
{
    "editor.save": "Save"
}
```

------------------------------------------------------------------------

## Локализация в доменной модели

Внутри системы нельзя хранить отображаемые строки напрямую.

Например:

Плохо:

``` ts
interface Template {
    name: string
}
```

если name является системным названием.

Лучше:

``` ts
interface Template {
    nameKey: string
}
```

Например:

``` json
{
    "nameKey": "template.character"
}
```

А отображение:

``` ts
t(template.nameKey)
```

------------------------------------------------------------------------

## Пользовательский контент

Важно разделять:

1.  системный текст приложения;
2.  пользовательский текст мира.

Системный текст:

-   кнопки;
-   меню;
-   ошибки;
-   подсказки;
-   настройки;
-   интерфейс редактора.

Он хранится в localization files.

Пользовательский текст:

-   описания GameObject;
-   страницы;
-   блоки Markdown;
-   заметки;
-   лор мира.

Он НЕ переводится автоматически и хранится как пользовательский контент.

Пример:

    Project
    |
    ├── Localization
    |       └── system UI
    |
    ├── GameObjects
    |       └── user lore
    |
    └── Pages
            └── markdown content

------------------------------------------------------------------------

## Локализация Template системы

Templates могут содержать локализуемые системные поля.

Например:

Character Template:

``` json
{
    "titleKey": "template.character.title",
    "descriptionKey": "template.character.description"
}
```

В разных языках:

English:

``` json
{
    "template.character.title": "Character",
    "template.character.description": "A person or creature in your world."
}
```

Russian:

``` json
{
    "template.character.title": "Персонаж",
    "template.character.description": "Существо или человек в вашем мире."
}
```

------------------------------------------------------------------------

## Локализация Example Projects

Example Projects могут иметь несколько языков.

Например:

    Examples/

    Fantasy World/

    ├── project.json
    ├── locales/
    │   ├── en/
    │   └── ru/
    │
    ├── assets/
    └── data/

При этом сам лор мира может иметь собственные версии:

    Page:
        Main

    Translations:

        en.md
        ru.md

Это позволит создавать официальные переводы демонстрационных миров.

------------------------------------------------------------------------

## Локализация пользовательских проектов

В будущем пользователь может захотеть создавать миры с несколькими
языками.

Например:

    Cool Fantasy

    Pages:

    Character/Alex

    ├── en.md
    ├── ru.md
    └── jp.md

Это не является обязательным для MVP, но архитектура должна не мешать
такой возможности.

------------------------------------------------------------------------

## Правило разработки

Любой новый UI-текст должен появляться следующим образом:

1.  Создать ключ локализации.
2.  Добавить значение в основной язык.
3.  Использовать ключ в интерфейсе.
4.  При необходимости добавить переводы.

Запрещено добавлять:

``` tsx
<Text>
    Settings
</Text>
```

Разрешено:

``` tsx
<Text>
    {t("settings.title")}
</Text>
```

## Рекомендуемая архитектура

    Presentation Layer
            |
            | uses translation keys
            ▼

    Localization Service

            |
            ├── en.json
            ├── ru.json
            ├── jp.json
            └── other languages


    Domain Layer

            |
            └── contains no UI strings

## MVP

Обязательно:

-   система ключей локализации;
-   английский язык как базовый;
-   возможность добавить русский язык;
-   отсутствие hardcoded UI текста;
-   хранение переводов отдельно от кода.

Позже:

-   пользовательские языки;
-   community translations;
-   автоматический экспорт строк;
-   AI-перевод;
-   синхронизация переводов через SaaS.
